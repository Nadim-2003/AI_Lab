# Emergency allocation CSP: design before implementation

CSP = (X, D, C). Each requirement quantity expands into individual slots X=(incident ID, requirement index, unit index). D(X) contains compatible available physical resources with a shortest accessible response route meeting the incident's deadline. For a patient slot the value is (resource, hospital), with a compatible reachable transport route and enough beds. Resource units have category, capabilities, passenger/personnel/equipment capacity, costs, current/home nodes and availability/release time.

C1 type, C2 availability, C4 response deadline, C5 accessible roads, C6 per-slot capacity/capability and C8 route feasibility filter unary domains. C3 physical exclusivity is binary. C9 requires all slots for full service. C10 includes a global cumulative hospital bed constraint. C7 is a global total dispatch plus distance operating cost budget. C11 severity then deadline is a soft variable-order policy; MRV precedes severity when enabled, with degree as optional tie-breaker. C12 systematic search resolves competing domains, rather than silently breaking a hard rule. Hospital pair incompatibility can be propagated by AC-3, but cumulative beds and budget remain global checks. Pair consistency cannot prove global feasibility.

Assumptions: snapshot dispatch, no resource reuse within a solve, even when service times differ. Request timestamps are minutes from the scenario epoch; deadlines are relative response-time limits in minutes; arrival is request time plus response travel. All requests are known to the central controller. Resources busy beyond a request time are excluded. Patient transport occurs after response and modeled service duration; transport time is reported separately and does not count toward the response deadline. Hospital beds are conservatively reserved across the snapshot, with no modeled discharge. Each transported patient is counted exactly once on an ambulance slot. Other resource capacities are per requirement slot, not pooled implicitly. Costs are simulated BDT, speeds and traffic are simulated, never live traffic estimates. No claim of optimal allocation or maximal partial allocation.

Backtracking searches systematically, CBJ returns responsible assigned variables and propagates conflict sets, forward checking trails/restores pruned values, and AC-3 enforces binary arc consistency as preprocessing (optional maintaining arc consistency during search). Budget and cumulative bed checks remain active in every method. Local search reports unresolved raw violations and returns only an independently validated feasible subset, with an explicit bounded-search status unless complete. All methods share the same domains and validator.

Small example: fire F requires slots F/fire/0 and F/ambulance/0; medical M requires M/ambulance/0. With FT1, AM1 and AM2, F gets FT1+AM1 and M gets AM2 if routes/deadlines/budget/beds permit. With only AM1, both cannot be fully served: exclusivity prevents assigning AM1 twice. A partial result distinguishes a partly served fire from an unserved medical request. This subset is not proven maximum. A dedicated binary fixture demonstrates CBJ skipping an unrelated decision; tests compare against exhaustive enumeration.

Routing policy: each origin/destination pair uses one deterministic fastest-time accessible path. A blocked road triggers an alternative accessible shortest-time path if one exists. The CSP chooses responders and hospitals; it does not jointly enumerate slower/cheaper routes. Feasibility/infeasibility statements are relative to this fixed routing policy and snapshot model, not every possible real-world routing/scheduling policy.
